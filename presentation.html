Industry Context & Pain Points

The Cloud Shift-Left Challenge

Why traditional IaC auditing and compliance workflows fall short

❌ Shift-Left Blindspots

  • Critical misconfigurations (open SSH/RDP, public S3 buckets, wildcard IAM) slip through code reviews.
  • Inconsistent security benchmarks between AWS, Azure, and GCP confuse platform engineers.
  • Monolithic security scanners fail when integrated into headless CI/CD automation.

❌ Opaque & Risky Tooling

  • Tools that contact cloud APIs require high-privilege credentials, creating credential leakage risks.
  • Black-box risk scoring models that cannot explain why a penalty was applied.
  • The Dangerous Assumption: Scanners silently dropping unsupported resources and falsely claiming "0 issues found".
Core Value Proposition

The InfraGuard Approach

Deterministic, verifiable, and decoupled static infrastructure security

1. Decoupled Architecture

FastAPI backend with OpenAPI docs. Streamlit dashboard consumes strictly public REST APIs. Usable anywhere: curl, CLI, or UI.

2. Deterministic Scoring

Mathematical penalty deductions from 100 with explainable risk bands: LOW, MODERATE, HIGH, and CRITICAL.

3. Zero Credential Risk

Evaluates parsed Abstract Syntax Trees (AST). Never contacts AWS, Azure, or GCP. No shell execution. No terraform binaries.

4. Honest Status Semantics

Explicit 4-state lifecycle: PASS, FAIL, NOT_EVALUATED, and UNSUPPORTED. Unknown resources are never treated as compliant.

5. In-Flight Secret Redaction

Automatic scrubbing of access keys, passwords, private keys, and API tokens prevents credentials from leaking into reports.

Boundary Guarantees

  • API First: All scanner features accessible via REST endpoints (/health, /providers, /rules, /scans).
  • Client Independence: Frontend imports zero backend models, rule classes, or SQLAlchemy sessions.
  • Memory Safe: Files parsed directly from memory buffers without temporary disk writes.
  • Persistence Across Reboots: Scans, findings, and diagnostic metadata persist in SQLite WAL mode.

Mathematical Rigor

Transparent Risk Scoring & Semantics

Reproducible mathematical formulas replace arbitrary risk ratings

Deduction Formula

$$\text{Risk Score} = \max\left(0, 100 - \sum \text{Finding Penalties}\right)$$

  • Critical: 25 points deduction (Immediate threat)
  • High: 15 points deduction (Significant vulnerability)
  • Medium: 7 points deduction (Defensive deficiency)
  • Low: 2 points deduction (Informational hygiene)

Defense-in-Depth

Threat Model & Hardened Ingestion

Protecting the auditor from malicious uploads, parser abuse, and secret leaks

🛡️ Anti-RCE Safe Parsers

PyYAML SafeLoader augmented with custom AWS intrinsic scalar constructors prevents arbitrary Python deserialization exploits.

🛡️ Path Traversal Immunity

Filenames are scrubbed via Path(filename).name. Files are streamed in memory without writing uploaded code to the server disk.

🛡️ In-Flight Secret Scrubbing

Recursive regex scrubber redacts credentials, passwords, AWS keys (AKIA...), and RSA private keys before reports are generated.

Ingestion Guardrails

  • Max single file size: 5 MB
  • Max batch upload size: 20 MB / 50 files
  • Strict extension whitelist: .tf, .yaml, .yml, .json

Local Boundary Warning

The unauthenticated MVP is engineered for local workstations or private CI runners. Public exposure on 0.0.0.0 is explicitly warned against in documentation.

Interactive User Experience

The InfraGuard User Journey

Fast, intuitive, and actionable security reporting

1. Dynamic Submission

Provider dropdown automatically filters format options (e.g. AWS shows Terraform & CloudFormation; Azure/GCP show Terraform). Client-side validation catches empty files instantly.

2. Interactive Results

Sub-second static audit generates interactive Plotly severity donut charts, overall risk gauge, and collapsible finding cards showing exact line evidence and step-by-step remediation.

3. Audit Trail & Export

Past audits are recorded in a searchable SQLite history log with one-click reload. Audit reports download immediately in standardized JSON or CSV formats.
